# 인수 기준과 구현 단계

[개발 명세 목차](README.md) · 설계 명세 v1.1 · 구현 및 실기 검증 전

## 9. 선택 확장 (v1 합격 후에만)

AI가 직접 특정 창으로 캡처 대상을 바꾸는 기능은 편리하지만, 창 목록 자체가 개인 정보를 포함할 수 있고 OBS의 소스 설정이 다른 창으로 연결될 수 있다. v1에서 사전 등록 장면 전환만 지원하는 이유다.

확장 시 `GetInputPropertiesListPropertyItems`로 승인된 창 캡처 소스의 `window` 속성 후보를 얻고, 실제 Windows OBS에서 속성명과 값 형식을 확인한다. 사용자 허용 실행 파일/창에 해당하는 후보만 노출하며 임의 창 목록 전체를 반환하지 않는다. 사용자가 고른 값으로 `SetInputSettings`의 허용된 단일 속성만 변경하고, 다른 필드는 거부한다. 생성·삭제·URL·임의 입력 설정은 여전히 금지한다. 창 재검증 및 승인, 녹화 중 변경 금지, 변경 전후 상태 검사와 롤백 테스트를 통과해야 한다. 자동 녹화 시나리오·영상 미리보기·멀티 클라이언트 브로커도 별도 확장으로 취급한다.

## 10. 검증 및 인수 테스트

실제 OBS를 건드리지 않는 자동 단위/통합 테스트를 먼저 실행한다. 거부 시험에서 위험 RPC가 가짜 OBS 서버에 한 건도 도달하지 않아야 한다. 실제 OBS 시험은 사용자 승인 후 전용 테스트 프로필과 민감정보 없는 테스트 창으로만 수행한다. 방송 차단 시험은 모의 상태로 검증하며 실제 방송을 시작하지 않는다.

| ID | 시험 | 합격 기준 |
|---|---|---|
| T01 | 정상 연결 및 상태 | MCP 도구 목록 확인, 정확한 OBS 버전/상태 출력 |
| T02 | OBS 미실행/틀린 암호/인증 꺼짐 | 명확한 오류, 무한 재시도 없음, 비밀번호 노출 없음 |
| T03 | 외부 URL, IPv6 우회, 프록시 환경변수, 리다이렉트 | 루프백 외 연결 시도 0건, 요청 차단 |
| T04 | 금지 RPC·원시 요청·추가 인자 | 모든 요청 차단, OBS까지 전송되지 않음 |
| T05 | 승인 취소·타임아웃·가짜 confirmed 인자 | 캡처/녹화 시작 요청 0건 |
| T06 | 허용되지 않은 장면·창, 다른 프로필, 예상 외 소스/필터/오디오 | 거부, 자동 전체 화면 대체 없음 |
| T07 | PNG 정상 캡처 | 지정 루트에 새 PNG 생성, 실제 화면·크기 확인, 모델에 이미지 바이트 미반환 |
| T08 | 잘못된 base64/과대 이미지/손상 PNG | 저장 거부 또는 해당 호출의 불완전 파일만 정리 |
| T09 | 경로 탈출·UNC·ADS·예약명·junction·symlink·기존 파일 | 루트 밖 파일 생성 및 덮어쓰기 0건 |
| T10 | 실제 녹화 시작→상태→종료 | OBS REC 표시, 결과 파일 루트 내 저장, 재생 가능 확인 |
| T11 | 일시정지·재개·중복 시작·잘못된 세션 | 올바른 상태 전이, 지원하지 않으면 명시 오류, 기존 수동 녹화 보존 |
| T12 | 방송/가상 카메라 활성 모의 상태 | 캡처/변경 요청 거부, 방송 제어 요청 0건 |
| T13 | 제한 시간·용량·디스크 부족 | 자신이 시작한 녹화 안전 정지 또는 명확한 실패 경고 |
| T14 | OBS 연결 끊김·MCP 정상/강제 종료 | 성공 가장 없음, 정상 종료 시 정지 시도, 강제 종료 잔여 위험 및 수동 복구 확인 |
| T15 | 두 MCP 동시 실행 | 하나만 제어권 획득, 다른 서버는 BUSY 또는 명시 오류 |
| T16 | 비밀·캡처 데이터 로그 검사 | 실제 비밀번호, 인증 응답, 원시 이미지, 개인 창 제목 및 불필요한 절대 경로 미포함 |
| T17 | 런타임 네트워크 검사 | MCP 프로세스에서 예상된 루프백 통신 외 외부 연결 없음 (OBS 자체 통신과 구분) |
| T18 | Codex / Claude Code 실제 연결 | 각 클라이언트에서 상태→스크린샷→녹화→종료 성공, 순차 검증 |
| T19 | 창 최소화/종료/제목 변경/장면 전환 | 타 창으로 무단 전환하지 않음, 불확실하면 실패/정지/경고 |
| T20 | 실제 녹화 무음 검증 | 오디오 입력이 포함되지 않는 설정 확인, 결과 음성/오디오 트랙 검사 |

실기 검증 시 사용할 사용자 요청 예시:

> OBS MCP로 승인된 Unity Game 장면의 상태를 확인해. 내 로컬 승인 후 PNG 스크린샷을 한 장 저장하고, 승인된 같은 창을 10초간 무음 녹화한 뒤 종료해. 저장된 파일의 상대 경로와 실제 녹화 상태를 알려줘. 외부 전송이나 OBS 일반 프로필 변경은 하지 마.

10초 녹화는 MCP 감시자가 종료한다. 호스트는 저장된 세션 ID로 결과를 조회한다. 사용자 로컬 환경에서 실제 영상 재생, 타깃 일치, 무음 확인까지 완료해야 최종 합격이다.

### 10.1 우선 인수 시험과 성능 측정

| ID | 시험 | 합격 기준 |
|---|---|---|
| T21 | 10초 자동 종료 후 조회 및 재중지 | `TIME_LIMIT`, 동일한 검증된 상대 경로와 바이트 수 반환, 중지 RPC는 최초 1건. 재실행 후 보관 기간 내 결과 조회 가능. Codex와 Claude Code에서 각각 재생·무음 확인 |
| T22 | 연결 단절 중 수동 녹화로 교체 | 재연결 뒤 이전 ID에 `STATE_UNKNOWN`. 활성 수동 녹화 중지·일시정지·재개 RPC 0건 |
| T23 | 승인 창이 열린 중 녹화 한도 도달 | 다음 1초 감시 주기에 소유 녹화 중지 시작. 만료 이후 클릭에서 캡처 송신 0건 |
| T24 | 중복 창·전환 지연 | 설정과 실창이 불일치하거나 전환이 완료되기 전 StartRecord·PNG 요청 0건 |
| T25 | PNG 전송 상한 | 1 MiB를 넘는 정상 메시지는 저장. 44 MiB 전송·32 MiB PNG·4096 픽셀 상한을 각각 초과하면 저장 0건, 제어 연결 유지 |
| T26 | 출력 모드·검증 실패 | 필수 프로필 키가 검증되지 않으면 StartRecord 0건. 종료 경로가 범위를 벗어나거나 기존 파일이면 결과 경로 미반환 |
| T27 | Python 실행 격리 | 작업 폴더와 `PYTHONPATH`에 동명 모듈이 있어도 전용 가상환경의 설치본만 실행 |

성능 시험은 같은 Unity 장면·동작을 무녹화, 1080p 하드웨어 인코딩 녹화, 같은 녹화의 중간에 PNG 1회 캡처하는 조건에서 각각 60초간 실행한다. OBS 통계에서 렌더링 지연과 인코딩 지연 프레임 수의 구간별 증분을 기록한다. Unity 프레임 시간 p95와 PNG 처리 구간의 최대 프레임 시간, 실제 해상도·FPS·인코더를 함께 기록한다. 하드웨어 인코딩을 쓸 수 없는 환경은 해당 조건을 미측정으로 표시한다.

## 11. 구현 단계 및 최종 제출물

1. 공식 사양·SDK 버전 및 의존성 검토, 위협 모델 정리, 설계 확정.
2. 로컬 정책·RPC 제한·인증·경로·승인 UI·동시성 통제 구현.
3. 상태 확인·장면 선택·PNG 저장 구현 및 단위 테스트.
4. 녹화 상태 머신·감시·오류 복구 구현 및 모의 통합 테스트.
5. 공급망 검사, 정적 보안 검토, 비밀 검색, 네트워크/파일 경계 시험.
6. 사용자 승인 후 전용 OBS 프로필에서 실제 테스트 및 클라이언트 순차 연결 검증.
7. 검증 결과를 제출하고 사용자가 승인한 뒤 설치/등록 확정.

최종 제출물: 전체 소스, 잠금 파일, 설치·제거·비밀번호 등록·긴급 정지 가이드, 도구 목록 및 RPC 허용 목록, 테스트 코드와 결과(통과/실패/미실행 구분), 사용 의존성 및 라이선스, 보안 검토 결과 및 잔여 위험, 실제 OBS 시험 버전·클라이언트 버전·결과물 경로. 사용자가 직접 요청하지 않았다면 GitHub 공개, 커밋·푸시, 기존 Unity 프로젝트 수정, 전역 설정 변경은 하지 않는다.

**완료 조건:** 필수 기능 구현과 자동 테스트 통과만으로 실제 OBS 연결 성공을 주장하지 않는다. 실제 Windows OBS와 Codex 및 Claude Code에서 T07/T10/T18/T20/T21을 검증하고 모의 회귀 시험 T22–T27의 결과를 확인한 후에만 운영 가능으로 보고한다. 미실행·실패 시험, 접근 제한, 미검증 의존성은 그대로 표시한다. 확인하지 않은 사항에 대해 '완전히 안전하다'는 표현을 사용하지 않는다.

## 12. 코딩 에이전트에게 전달할 최종 작업 지시

> 이 문서를 구현 계약으로 사용하여 독립적인 Windows 로컬 OBS MCP 서버를 개발해라. 먼저 공식 OBS WebSocket 5.x 및 MCP SDK 사양과 설치 환경을 확인하고 구현 계획·예상 의존성·위협 모델을 제시해라. 보안 정책과 RPC 허용 목록을 구현한 뒤 스크린샷/녹화 기능을 구현하고 자동 테스트를 실행해라. 기능을 위해 보안 제한을 완화하지 말고, 공식 API에서 확인되지 않은 기능은 실제 지원 여부를 확인하거나 미지원으로 처리해라. 실제 비밀번호를 요구하거나 읽어서 보여주지 말고, 사용자가 로컬에서 직접 등록하도록 안내해라. 실제 OBS 설정 변경·실기 녹화·Codex/Claude 설정 등록·전역 설치·커밋/푸시는 사용자 승인 이후에만 진행해라. 테스트 결과와 잔여 위험, 수동 긴급 정지 및 제거 방법까지 제출해라. 네트워크 제한 등으로 검증하지 못한 내용은 성공으로 표시하지 마라.
