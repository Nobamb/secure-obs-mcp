### 4.1 사용자 승인과 자동화

로컬 Windows 승인 창에는 작업 종류, 대상, 무음 여부, 저장 위치, 녹화 제한을 검토된 고정 양식으로 표시한다. 창 제목 등 외부 문자열의 제어문자와 과도한 길이를 제거한다. 승인은 해당 도구 호출·대상·인자·검증한 OBS 상태에 묶어 한 번 사용한다.

기본 승인 대기 한도는 30초다. 첫 부수 효과 전 재검증과 실행 및 응답에 필요한 시간을 포함해 전체 도구 타임아웃 안에 끝나도록 승인 창을 먼저 닫는다. Codex 기본 도구 타임아웃은 60초다. 두 클라이언트에 설정한 유효 타임아웃을 설치 시 확인하며, 실행 시간 예산이 모자라면 만료를 앞당기거나 작업을 거부한다. 기한 이후 클릭, 취소되거나 닫힌 호출의 승인, UI 생성 실패는 무효다. 승인 후 첫 부수 효과를 보내기 직전에 만료와 취소를 다시 확인한다.

승인 UI 대기와 이미지 디코딩·파일 검증 중에는 녹화 상태 잠금을 해제한다. 실제 상태 변경은 짧은 구간에서 직렬화한다. 시간 한도나 안전 위반으로 인한 소유 녹화 중지는 승인 대기 중이어도 다음 감시 주기에 시작한다. 클라이언트가 시작 요청 송신 뒤 취소해도 송신 결과와 소유 녹화 감시는 계속 처리한다.

반복 테스트 편의를 위해 선택적으로 사용자가 직접 승인한 시간 제한 캡처 세션을 지원할 수 있다. 이 세션은 고정 대상·허용 작업·종료 시각·호출 횟수에 묶이며 MCP 호출로 발급·연장할 수 없다. v1은 호출별 승인만 구현해도 합격이다. 기존 녹화 종료 및 안전 정지는 추가 승인으로 지연하지 않는다. 에이전트가 시작하지 않은 수동 녹화는 기본적으로 건드리지 않는다.

### 4.2 인증 정보

우선안: Windows Credential Manager 등 로컬 자격증명 저장소에서 실행 시 읽는다. 사용자가 직접 등록하는 별도 설정 CLI/GUI를 제공하되 MCP 도구로 노출하지 않는다. 대체안: 사용자가 실행 환경에 직접 주입하는 `OBS_MCP_PASSWORD` 환경변수. 환경변수는 동일 사용자 프로세스나 디버거에 노출될 수 있으므로 별도 신뢰 경계가 아니다. 저장소·`.mcp.json`·`config.toml`에 실제 비밀번호를 쓰지 않는다. 에이전트에게 비밀번호 입력이나 파일 읽기를 요청하지 않는다. OBS 챌린지·응답 인증값·원시 메시지도 로그 금지.

### 4.3 파일 안전성 (Windows)

- 사용자만 수정하는 로컬 설정에서 절대 경로 루트를 선택한다. 예시: `D:\OBS-Captures` (실제 존재하는 로컬 NTFS 경로 사용). 자동 설정은 하지 않는다.
- 하위 `screenshots`, `recordings`, `logs`를 분리하고 캡처 루트에 쓰기 권한을 최소화한다. UNC·네트워크 드라이브·장치 경로·클라우드 동기화 폴더는 사용하지 않는다.
- `..`, 절대 경로 인자, 슬래시, NTFS ADS(`:`), 예약 장치명, 후행 점/공백, 심볼릭 링크·junction·기타 reparse point를 거부한다. 정규화 및 실제 경로를 확인하고 루트 하위인지 Windows 경로 규칙으로 비교한다. 문자열 prefix 비교만 사용하지 않는다.
- 외부에서 파일명을 받지 않고 UTC 시각과 난수/UUID를 이용해 서버가 생성한다. 스크린샷은 배타적 신규 생성(`xb` 또는 동등 API), 실패 시 해당 호출이 생성한 불완전 파일만 정리한다. 기존 파일은 절대 수정하지 않는다.
- 부모 디렉터리 바꿔치기(TOCTOU) 위험을 고려한다. 가능하면 파일 핸들 기준 최종 경로 및 reparse 속성을 검사하고, 신뢰된 ACL의 전용 루트에서만 사용한다. 동일 사용자 공격까지 완전히 막을 수 없음을 문서화한다.
- OBS가 녹화 파일을 쓴다. 전용 프로필의 고급 출력에서 표준 녹화와 일반 MKV만 지원하고, 검증된 고유 파일명 규칙과 덮어쓰기·자동 분할·자동 리먹스 해제를 요구한다. 시작 직전 `GetRecordDirectory`로 전용 `recordings`의 실제 경로를 확인한다. 설치·검증한 OBS 버전별로 검토된 `GetProfileParameter` 키와 유효값을 고정한다. 이 키 목록은 출력 모드·녹화 유형·컨테이너·파일명·덮어쓰기·자동 분할·자동 리먹스를 모두 다룬다. 키나 값의 의미 또는 실제 적용 여부를 확인할 수 없으면 녹화 시작을 거부한다.
- 시작 직전 기존 결과의 이름 또는 파일 식별자를 기록한다. 종료 뒤 검증된 세션의 `outputPath`를 실제 경로와 파일 핸들 기준으로 검사한다. 전용 루트 안에 새로 생성된 일반 MKV이며 크기가 0보다 크고 안정화될 때만 파일 결과를 확정한다. 링크·경로 불일치·기존 파일 재사용·파일 부재는 실패로 응답하고 파일을 삭제하거나 이동하지 않는다. 전용 프로필의 검증 이후에는 OBS UI와 다른 제어 도구로 출력 설정을 변경하지 않는다. 이 제약은 OBS의 실제 쓰기와 MCP의 검증 사이에 적용되는 운영 조건이다.
- 한도 기본값은 최소 디스크 여유 1 GiB, 녹화 출력 2 GiB, 녹화 시간 120초다. 시간 설정의 상한은 600초다. 디스크 여유가 기준 이하이면 시작을 거부한다. 녹화 중 한도는 [녹화 상태 머신](feature-design.md#64-녹화-상태-머신)의 감시에 적용하고, 실제 파일 크기와 정지 지연에 따른 초과를 종료 결과에 기록한다. 감사 로그는 크기 제한 및 회전 정책을 적용한다.
