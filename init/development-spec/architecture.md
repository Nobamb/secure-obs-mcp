# 아키텍처와 개발 범위

[개발 명세 목차](README.md) · 설계 명세 v1.1 · 구현 및 실기 검증 전

## 1. 프로젝트 목표

기존의 소규모 서드파티 OBS MCP 서버를 설치하지 않고, OBS Studio의 공식 obs-websocket 5.x API를 이용하는 최소 권한의 로컬 MCP 서버를 자체 개발한다. 게임 개발 중 특정 프로그램 창의 정지 화면 및 영상 캡처, UI·애니메이션 검증, 테스트 결과 보존을 자동화한다. 예를 들어 Unity 또는 Sub-Terra 게임 창에서 보관함 개폐, 광부 애니메이션, UI 변경 전후를 녹화하고 지정된 로컬 폴더에 결과물을 저장한다.

**최우선 원칙:** 기능이 보안 정책과 충돌하면 기능을 거부하고 원인을 안내한다. 안전을 이유로 성공을 가장하거나, 보안 검사를 우회하는 대체 경로를 실행하지 않는다. 기존 OBS MCP 저장소의 코드·바이너리·스킬을 재사용할 필요는 없다. 공식 사양과 검증 가능한 최소 의존성으로 구현한다.

### 1.1 필수 기능 (v1.0)

- OBS 연결 및 인증 상태, 버전, 녹화 가능 여부 확인.
- 사용자가 사전에 허용한 OBS 장면·캡처 소스 조회 및 선택.
- 허용된 대상의 PNG 스크린샷 촬영 및 안전한 로컬 파일 저장.
- 녹화 시작, 일시정지, 재개, 종료 및 상태 확인.
- 녹화 완료 파일 위치, 크기, 재생 가능 여부 확인 절차 제공.
- 녹화 최대 시간, 저장 공간 최소치, 동시 실행 제한 및 수동 긴급 정지.
- Codex와 Claude Code에 로컬 stdio 방식으로 등록 가능.

### 1.2 범위 제외

생방송, 스트림 키 조회/변경, 가상 카메라, 리플레이 버퍼, 웹캠·마이크 활성화, 전체 디스플레이 캡처, 브라우저/URL 소스, 원격 OBS, 임의 핫키, 임의 OBS 설정 변경, 파일 삭제·덮어쓰기·업로드, 화면 자동 전송, 쉘 실행, 플러그인 설치, OBS 원격 실행은 v1에서 제공하지 않는다. 창 생성·크기 변경 및 Unity 게임 조작은 별도 에이전트 도구의 책임이다. 자동 창 목록 조회 및 캡처 대상 변경은 [선택 확장](acceptance.md#9-선택-확장-v1-합격-후에만)의 선택 확장으로 분리한다.

## 2. 아키텍처 및 신뢰 경계

```text
Codex CLI / Claude Code (로컬 에이전트)
               │ MCP stdio (JSON-RPC)
               ▼
       secure-obs-mcp
       ├─ 타입·스키마 검증
       ├─ 로컬 정책 및 대상 허용 목록
       ├─ 사용자 승인 UI / 녹화 세션 관리
       ├─ OBS RPC 허용 목록·응답 검증
       ├─ 경로 검증 / 로컬 감사 로그
       └─ 로컬 OBS 제어 연결 + 요청당 PNG 전용 연결
               │ ws://127.0.0.1:4455
               ▼
       OBS Studio + 내장 obs-websocket
               │
               ▼
       사용자 지정 로컬 캡처 폴더
```

OBS WebSocket은 OBS 28 이상에 기본 포함된다. MCP는 별도 구현하는 어댑터이며 OBS 자체를 패치하지 않는다. OBS WebSocket의 인증은 연결 인증이지 개별 명령 권한 제한이 아니므로, MCP의 요청 검증이 필수다. **MCP가 로컬이라는 사실만으로 OBS 서버가 외부에 노출되지 않는다는 보장은 없다.** Windows 방화벽의 LAN 인바운드 및 인터넷 포트 포워딩을 별도로 확인한다.

신뢰 대상으로 간주하는 것은 사용자, 검토 완료된 MCP 코드·고정 의존성, 사용자 전용 설정, 승인된 OBS 장면이다. 에이전트의 입력·도구 인자, 창 제목, OBS에서 반환하는 이름·문자열·경로는 신뢰하지 않는다. 이 문자열을 지시문, 코드, 쉘 명령 또는 URL로 해석하지 않는다.

이 설계는 MCP 자체에 대한 최소 권한 통제다. 동일 Windows 계정에서 별도의 쉘·파일 편집 권한을 가진 에이전트는 설정 수정, OBS 직접 연결, 화면 파일 읽기 등을 할 수 있다. 해당 공격까지 막으려면 에이전트 샌드박스, 별도 OS 계정/권한 분리 또는 별도 신뢰 브로커가 필요하다. 동일 사용자 권한 아래에서 DPAPI나 파일 ACL만으로 완전한 비밀 격리를 주장하지 않는다.

## 3. 구현 기술 및 공급망 관리

기본 구현안은 Python 3.12 이상(선택한 SDK·Windows 환경 호환성 확인), 공식 MCP Python SDK `mcp`, 검토된 WebSocket 클라이언트 라이브러리를 사용한다. OBS RPC는 공식 프로토콜의 필요한 요청만 담은 얇은 어댑터로 구현한다. SDK 세대별 API가 달라질 수 있으므로 설치 시 검증한 안정 릴리스의 문서와 실제 API를 기준으로 구현하고, 다른 세대 예제를 혼용하지 않는다. OBS 인증 알고리즘은 공식 사양 그대로 적용하며 자체 암호화 방식은 설계하지 않는다.

- 런타임 의존성은 최소화하고 직접·전이 의존성 모두 잠금 파일에 버전·해시를 고정한다. 해시 검증 설치 및 취약점 검사 결과를 제출한다.
- 출처가 확인된 패키지 및 배포처만 사용한다. 외부 프로젝트 설치 스크립트, 출처 불명 바이너리, `curl | shell` 방식, 매 실행마다 최신 패키지를 내려받는 방식은 금지한다.
- 런타임은 로컬 가상환경의 고정된 Python 실행 파일로 시작한다. 자동 업데이트, 텔레메트리, 원격 오류 수집, 외부 다운로드는 구현하지 않는다.
- 관리자 권한, 시스템 서비스 등록, 레지스트리 자동 변경, 시작 프로그램 등록을 요구하지 않는다. 방화벽 변경은 필요한 경우 사용자에게 수동 절차만 제시한다.
- 소스·테스트·빌드 절차·잠금 파일·라이선스 및 패키지 목록을 제공한다. 보안 검사에서 나온 취약점은 근거와 함께 처리하고 미해결 중요 취약점은 설치 차단 사유로 기록한다.
