# Secure OBS MCP — 개발 및 보안 명세서

- 문서 버전: 1.1 | 수정일: 2026-11-27
- 대상: Windows 10/11, OBS Studio, 로컬 Codex CLI/IDE 및 Claude Code
- 용도: AI 코딩 에이전트에게 전달할 구현 요구사항 및 인수 테스트 기준
- 상태: 설계 명세서. 구현 및 실제 OBS 시험은 별도 수행한다.

1.1의 개정 사항은 자동 종료 결과 조회, 녹화 소유권, 창 및 장면 확인, 녹화 출력과 한도, Python 실행 격리, PNG 전송, 승인 대기, OBS·Unity 성능 측정에 반영했다. [우선 인수 시험](#101-우선-인수-시험과-성능-측정)에서 세 가지 회귀 시나리오를 먼저 검증한다.

## 1. 프로젝트 목표

기존의 소규모 서드파티 OBS MCP 서버를 설치하지 않고, OBS Studio의 공식 obs-websocket 5.x API를 이용하는 최소 권한의 로컬 MCP 서버를 자체 개발한다. 게임 개발 중 특정 프로그램 창의 정지 화면 및 영상 캡처, UI·애니메이션 검증, 테스트 결과 보존을 자동화한다. 예를 들어 Unity 또는 Sub-Terra 게임 창에서 보관함 개폐, 광부 애니메이션, UI 변경 전후를 녹화하고 지정된 로컬 폴더에 결과물을 저장한다.

**최우선 원칙:** 기능이 보안 정책과 충돌하면 기능을 거부하고 원인을 안내한다. 안전을 이유로 성공을 가장하거나, 보안 검사를 우회하는 대체 경로를 실행하지 않는다. 기존 OBS MCP 저장소의 코드·바이너리·스킬을 재사용할 필요는 없다. 공식 사양과 검증 가능한 최소 의존성으로 구현한다.

### 1.1 필수 기능 (v1.0)

- OBS 연결 및 인증 상태, 버전, 녹화 가능 여부 확인.
- 사용자가 사전에 허용한 OBS 장면·캡처 소스 조회 및 선택.
- 허용된 대상의 PNG 스크린샷 촬영 및 안전한 로컬 파일 저장.
- 녹화 시작, 일시정지, 재개, 종료 및 상태 확인.
- 녹화 완료 파일 위치, 크기, 재생 가능 여부 확인 절차 제공.
- 녹화 최대 시간, 저장 공간 최소치, 동시 실행 제한 및 수동 긴급 정지.
- Codex와 Claude Code에 로컬 stdio 방식으로 등록 가능.

### 1.2 범위 제외

생방송, 스트림 키 조회/변경, 가상 카메라, 리플레이 버퍼, 웹캠·마이크 활성화, 전체 디스플레이 캡처, 브라우저/URL 소스, 원격 OBS, 임의 핫키, 임의 OBS 설정 변경, 파일 삭제·덮어쓰기·업로드, 화면 자동 전송, 쉘 실행, 플러그인 설치, OBS 원격 실행은 v1에서 제공하지 않는다. 창 생성·크기 변경 및 Unity 게임 조작은 별도 에이전트 도구의 책임이다. 자동 창 목록 조회 및 캡처 대상 변경은 §9의 선택 확장으로 분리한다.

## 2. 아키텍처 및 신뢰 경계

```text
Codex CLI / Claude Code (로컬 에이전트)
               │ MCP stdio (JSON-RPC)
               ▼
       secure-obs-mcp
       ├─ 타입·스키마 검증
       ├─ 로컬 정책 및 대상 허용 목록
       ├─ 사용자 승인 UI / 녹화 세션 관리
       ├─ OBS RPC 허용 목록·응답 검증
       ├─ 경로 검증 / 로컬 감사 로그
       └─ 로컬 OBS 제어 연결 + 요청당 PNG 전용 연결
               │ ws://127.0.0.1:4455
               ▼
       OBS Studio + 내장 obs-websocket
               │
               ▼
       사용자 지정 로컬 캡처 폴더
```

OBS WebSocket은 OBS 28 이상에 기본 포함된다. MCP는 별도 구현하는 어댑터이며 OBS 자체를 패치하지 않는다. OBS WebSocket의 인증은 연결 인증이지 개별 명령 권한 제한이 아니므로, MCP의 요청 검증이 필수다. **MCP가 로컬이라는 사실만으로 OBS 서버가 외부에 노출되지 않는다는 보장은 없다.** Windows 방화벽의 LAN 인바운드 및 인터넷 포트 포워딩을 별도로 확인한다.

신뢰 대상으로 간주하는 것은 사용자, 검토 완료된 MCP 코드·고정 의존성, 사용자 전용 설정, 승인된 OBS 장면이다. 에이전트의 입력·도구 인자, 창 제목, OBS에서 반환하는 이름·문자열·경로는 신뢰하지 않는다. 이 문자열을 지시문, 코드, 쉘 명령 또는 URL로 해석하지 않는다.

이 설계는 MCP 자체에 대한 최소 권한 통제다. 동일 Windows 계정에서 별도의 쉘·파일 편집 권한을 가진 에이전트는 설정 수정, OBS 직접 연결, 화면 파일 읽기 등을 할 수 있다. 해당 공격까지 막으려면 에이전트 샌드박스, 별도 OS 계정/권한 분리 또는 별도 신뢰 브로커가 필요하다. 동일 사용자 권한 아래에서 DPAPI나 파일 ACL만으로 완전한 비밀 격리를 주장하지 않는다.

## 3. 구현 기술 및 공급망 관리

기본 구현안은 Python 3.12 이상(선택한 SDK·Windows 환경 호환성 확인), 공식 MCP Python SDK `mcp`, 검토된 WebSocket 클라이언트 라이브러리를 사용한다. OBS RPC는 공식 프로토콜의 필요한 요청만 담은 얇은 어댑터로 구현한다. SDK 세대별 API가 달라질 수 있으므로 설치 시 검증한 안정 릴리스의 문서와 실제 API를 기준으로 구현하고, 다른 세대 예제를 혼용하지 않는다. OBS 인증 알고리즘은 공식 사양 그대로 적용하며 자체 암호화 방식은 설계하지 않는다.

- 런타임 의존성은 최소화하고 직접·전이 의존성 모두 잠금 파일에 버전·해시를 고정한다. 해시 검증 설치 및 취약점 검사 결과를 제출한다.
- 출처가 확인된 패키지 및 배포처만 사용한다. 외부 프로젝트 설치 스크립트, 출처 불명 바이너리, `curl | shell` 방식, 매 실행마다 최신 패키지를 내려받는 방식은 금지한다.
- 런타임은 로컬 가상환경의 고정된 Python 실행 파일로 시작한다. 자동 업데이트, 텔레메트리, 원격 오류 수집, 외부 다운로드는 구현하지 않는다.
- 관리자 권한, 시스템 서비스 등록, 레지스트리 자동 변경, 시작 프로그램 등록을 요구하지 않는다. 방화벽 변경은 필요한 경우 사용자에게 수동 절차만 제시한다.
- 소스·테스트·빌드 절차·잠금 파일·라이선스 및 패키지 목록을 제공한다. 보안 검사에서 나온 취약점은 근거와 함께 처리하고 미해결 중요 취약점은 설치 차단 사유로 기록한다.

### 4.1 사용자 승인과 자동화

로컬 Windows 승인 창에는 작업 종류, 대상, 무음 여부, 저장 위치, 녹화 제한을 검토된 고정 양식으로 표시한다. 창 제목 등 외부 문자열의 제어문자와 과도한 길이를 제거한다. 승인은 해당 도구 호출·대상·인자·검증한 OBS 상태에 묶어 한 번 사용한다.

기본 승인 대기 한도는 30초다. 첫 부수 효과 전 재검증과 실행 및 응답에 필요한 시간을 포함해 전체 도구 타임아웃 안에 끝나도록 승인 창을 먼저 닫는다. Codex 기본 도구 타임아웃은 60초다. 두 클라이언트에 설정한 유효 타임아웃을 설치 시 확인하며, 실행 시간 예산이 모자라면 만료를 앞당기거나 작업을 거부한다. 기한 이후 클릭, 취소되거나 닫힌 호출의 승인, UI 생성 실패는 무효다. 승인 후 첫 부수 효과를 보내기 직전에 만료와 취소를 다시 확인한다.

승인 UI 대기와 이미지 디코딩·파일 검증 중에는 녹화 상태 잠금을 해제한다. 실제 상태 변경은 짧은 구간에서 직렬화한다. 시간 한도나 안전 위반으로 인한 소유 녹화 중지는 승인 대기 중이어도 다음 감시 주기에 시작한다. 클라이언트가 시작 요청 송신 뒤 취소해도 송신 결과와 소유 녹화 감시는 계속 처리한다.

반복 테스트 편의를 위해 선택적으로 사용자가 직접 승인한 시간 제한 캡처 세션을 지원할 수 있다. 이 세션은 고정 대상·허용 작업·종료 시각·호출 횟수에 묶이며 MCP 호출로 발급·연장할 수 없다. v1은 호출별 승인만 구현해도 합격이다. 기존 녹화 종료 및 안전 정지는 추가 승인으로 지연하지 않는다. 에이전트가 시작하지 않은 수동 녹화는 기본적으로 건드리지 않는다.

### 4.2 인증 정보

우선안: Windows Credential Manager 등 로컬 자격증명 저장소에서 실행 시 읽는다. 사용자가 직접 등록하는 별도 설정 CLI/GUI를 제공하되 MCP 도구로 노출하지 않는다. 대체안: 사용자가 실행 환경에 직접 주입하는 `OBS_MCP_PASSWORD` 환경변수. 환경변수는 동일 사용자 프로세스나 디버거에 노출될 수 있으므로 별도 신뢰 경계가 아니다. 저장소·`.mcp.json`·`config.toml`에 실제 비밀번호를 쓰지 않는다. 에이전트에게 비밀번호 입력이나 파일 읽기를 요청하지 않는다. OBS 챌린지·응답 인증값·원시 메시지도 로그 금지.

### 4.3 파일 안전성 (Windows)

- 사용자만 수정하는 로컬 설정에서 절대 경로 루트를 선택한다. 예시: `D:\OBS-Captures` (실제 존재하는 로컬 NTFS 경로 사용). 자동 설정은 하지 않는다.
- 하위 `screenshots`, `recordings`, `logs`를 분리하고 캡처 루트에 쓰기 권한을 최소화한다. UNC·네트워크 드라이브·장치 경로·클라우드 동기화 폴더는 사용하지 않는다.
- `..`, 절대 경로 인자, 슬래시, NTFS ADS(`:`), 예약 장치명, 후행 점/공백, 심볼릭 링크·junction·기타 reparse point를 거부한다. 정규화 및 실제 경로를 확인하고 루트 하위인지 Windows 경로 규칙으로 비교한다. 문자열 prefix 비교만 사용하지 않는다.
- 외부에서 파일명을 받지 않고 UTC 시각과 난수/UUID를 이용해 서버가 생성한다. 스크린샷은 배타적 신규 생성(`xb` 또는 동등 API), 실패 시 해당 호출이 생성한 불완전 파일만 정리한다. 기존 파일은 절대 수정하지 않는다.
- 부모 디렉터리 바꿔치기(TOCTOU) 위험을 고려한다. 가능하면 파일 핸들 기준 최종 경로 및 reparse 속성을 검사하고, 신뢰된 ACL의 전용 루트에서만 사용한다. 동일 사용자 공격까지 완전히 막을 수 없음을 문서화한다.
- OBS가 녹화 파일을 쓴다. 전용 프로필의 고급 출력에서 표준 녹화와 일반 MKV만 지원하고, 검증된 고유 파일명 규칙과 덮어쓰기·자동 분할·자동 리먹스 해제를 요구한다. 시작 직전 `GetRecordDirectory`로 전용 `recordings`의 실제 경로를 확인한다. 설치·검증한 OBS 버전별로 검토된 `GetProfileParameter` 키와 유효값을 고정한다. 이 키 목록은 출력 모드·녹화 유형·컨테이너·파일명·덮어쓰기·자동 분할·자동 리먹스를 모두 다룬다. 키나 값의 의미 또는 실제 적용 여부를 확인할 수 없으면 녹화 시작을 거부한다.
- 시작 직전 기존 결과의 이름 또는 파일 식별자를 기록한다. 종료 뒤 검증된 세션의 `outputPath`를 실제 경로와 파일 핸들 기준으로 검사한다. 전용 루트 안에 새로 생성된 일반 MKV이며 크기가 0보다 크고 안정화될 때만 파일 결과를 확정한다. 링크·경로 불일치·기존 파일 재사용·파일 부재는 실패로 응답하고 파일을 삭제하거나 이동하지 않는다. 전용 프로필의 검증 이후에는 OBS UI와 다른 제어 도구로 출력 설정을 변경하지 않는다. 이 제약은 OBS의 실제 쓰기와 MCP의 검증 사이에 적용되는 운영 조건이다.
- 한도 기본값은 최소 디스크 여유 1 GiB, 녹화 출력 2 GiB, 녹화 시간 120초다. 시간 설정의 상한은 600초다. 디스크 여유가 기준 이하이면 시작을 거부한다. 녹화 중 한도는 §6.4의 감시에 적용하고, 실제 파일 크기와 정지 지연에 따른 초과를 종료 결과에 기록한다. 감사 로그는 크기 제한 및 회전 정책을 적용한다.

## 5. OBS RPC 및 MCP 도구 계약

### 5.1 OBS RPC 허용 목록

| 기능 | 허용 요청 |
|---|---|
| 연결 및 상태 | `GetVersion`, `GetRecordStatus`, `GetStreamStatus`, `GetVirtualCamStatus` |
| 전용 환경 검증 | `GetProfileList`, `GetSceneCollectionList`, `GetRecordDirectory`, `GetVideoSettings` |
| 장면 및 소스 검증 | `GetSceneList`, `GetCurrentProgramScene`, `GetSceneItemList`, `GetInputList`, `GetInputSettings`, `GetInputDefaultSettings`, `GetSourceFilterList`, `GetSpecialInputs`, `GetInputMute`, `GetInputAudioTracks` |
| 장면 선택 | `GetCurrentSceneTransition`, `GetSceneSceneTransitionOverride`, `GetCurrentSceneTransitionCursor`, `SetCurrentProgramScene` (허용 장면에 한정, 녹화/방송 중 금지) |
| 스크린샷 | `GetSourceScreenshot` |
| 녹화 | `StartRecord`, `PauseRecord`, `ResumeRecord`, `StopRecord` |
| 녹화 프로필 검사 | `GetProfileParameter` (검증한 OBS 버전별 녹화 section/key만 사용, 임의 인자 전달 금지) |

OBS 공식 사양 및 `GetVersion.availableRequests`에서 실제 지원 여부를 확인한다. 필요한 요청이 없으면 해당 기능을 비활성화하거나 안전하게 거부한다. `GetInputSettings` 등은 내부에서 검증할 때만 쓰고 원본 JSON을 모델에 반환하지 않는다. 허용 목록은 필요 최소치로 유지하며 테스트에 사용되지 않는 요청은 최종 구현에서 제거한다. 녹화 제어 연결은 Outputs 구독을 사용해 `RecordStateChanged`를 수신한다. PNG 전용 연결은 이벤트를 구독하지 않고 `GetSourceScreenshot`만 요청한다.

`StartStream`, `StartVirtualCam`, `SetStreamServiceSettings`, `GetStreamServiceSettings`, `CreateInput`, `SetInputSettings`, `SetRecordDirectory`, `SaveSourceScreenshot`, `CallVendorRequest`, `BroadcastCustomEvent`, 임의 `RequestBatch`, `TriggerHotkey*`, `SetProfileParameter`, 소스 삭제·생성, 플러그인·외부 프로그램 실행 등은 기본적으로 금지한다. 단순히 MCP 도구를 숨기는 것만으로는 부족하며 내부 RPC 송신 계층에서도 차단한다. §9 확장 시 별도 검토 후 필드 수준 허용 목록을 추가한다.

### 5.2 공개 MCP 도구

| 도구 | 인자 | 반환/제한 |
|---|---|---|
| `obs_status` | 없음 | 연결, 버전, 사용 가능 여부, 녹화/일시정지/방송 상태, 안전 정책 상태 |
| `obs_list_targets` | 없음 | 사용자 허용 대상 ID와 표시명만. 전체 창·장면 목록 반환 금지 |
| `obs_select_target` | `target_id` | 해당 허용 장면 선택. 녹화/방송 중 금지, 사용자 승인 필요 |
| `obs_screenshot` | `target_id`, `width?` | PNG 상대 경로, 이미지 크기, 바이트 수. 기본 원본 크기(설정 한도 내), 축소 폭 320~1920 등 검증된 범위 |
| `obs_record_start` | `target_id`, `duration_seconds?` | 세션 ID, 최대 종료 시각, 녹화 상태. 사용자 승인 필수 |
| `obs_record_status` | `session_id?` | 생략 시 현재 OBS 상태. 지정 시 해당 MCP 세션의 상태, 종료 사유 및 검증된 종료 결과 |
| `obs_record_pause` | `session_id` | MCP가 시작한 녹화만, 지원되는 출력 형식일 때 |
| `obs_record_resume` | `session_id` | 해당 세션만, 최초 최대 종료 시각 유지 |
| `obs_record_stop` | `session_id` | 소유 세션의 중지 및 결과 조회. 이미 종료했으면 관찰된 확정 결과 재반환. 검증 중에는 `FINALIZING` |

종료 결과는 `session_id`, `state`, `end_reason`, `relative_path`, `bytes`, `limit_exceeded`, `playback_verified`를 반환한다. 가능한 종료 사유는 `USER_STOP`, `TIME_LIMIT`, `SIZE_LIMIT`, `DISK_LOW`, `SAFETY_CHANGE`, `OBS_STOPPED`, `SERVER_SHUTDOWN`이다. `FINALIZING`은 파일 검증 진행 중이며 최종 경로를 반환하지 않는다. 종료를 확인했으나 유효한 파일을 확인하지 못하면 `FILE_NOT_FINALIZED`를 반환한다. 없거나 만료된 ID는 `SESSION_NOT_FOUND`, 소유권을 확정하지 못한 활성 세션은 `STATE_UNKNOWN`으로 응답한다. 종료 결과 조회에는 OBS 재연결을 요구하지 않는다.

타입 검증은 예상하지 못한 필드를 거부하는 것부터 시작한다. 문자열은 길이·형식 제한, 정수는 범위 검증(불리언·NaN·무한대 불허), 대상 ID는 설정에서 정확 일치해야 한다. 원시 RPC명·파일 경로·URL·비밀번호·쉘 문자열을 받는 도구는 만들지 않는다. MCP 메타데이터의 readOnly/destructive 힌트는 보조 설명일 뿐 보안 장벽이 아니다.

공통 반환 예시(실제 성공을 확인한 경우에만 `ok=true`):

```json
{
  "ok": true,
  "code": "SCREENSHOT_SAVED",
  "target_id": "unity_game",
  "relative_path": "screenshots/20261127T134700Z_8f9c.png",
  "width": 1920,
  "height": 1080,
  "bytes": 1458200
}
```

오류 코드 예: `OBS_UNAVAILABLE`, `AUTH_REQUIRED`, `AUTH_FAILED`, `UNSUPPORTED_RPC`, `TARGET_NOT_ALLOWED`, `TARGET_CHANGED`, `USER_DENIED`, `APPROVAL_TIMEOUT`, `STREAM_ACTIVE`, `RECORDING_NOT_OWNED`, `UNSAFE_PATH`, `DISK_LIMIT`, `BUSY`, `STATE_UNKNOWN`, `FILE_NOT_FINALIZED`. 예외 스택이나 원시 인증·설정 데이터를 반환하지 않는다. 파일 경로가 필요한 사용자는 로컬 루트와 상대 경로를 결합한다.

## 6. 기능 구현 상세

### 6.1 OBS 연결

공식 5.x의 Hello → Identify → Identified 절차를 구현한다. 인증이 필수인지 확인하고 공식 SHA-256 챌린지 방식을 사용한다. JSON 서브프로토콜, RPC 버전 협상, 요청 ID 일치, 응답 성공 상태를 확인한다. 제어 연결에서는 녹화 출력 이벤트를 구독하고 상태 조회와 교차 검증한다. PNG 전용 연결은 같은 루프백 주소로 승인당 하나만 열며, 캡처 RPC 종결 즉시 닫는다. 제어 메시지 한도는 1 MiB, PNG 메시지 한도는 44 MiB다. 메시지 큐와 요청 타임아웃에도 검증한 고정 상한을 적용한다. 프록시·리다이렉트·압축을 비활성화하고, 클라이언트 버전이 설정을 지원하는지 확인한다. stdout에는 MCP 메시지만, 로그는 제한된 stderr 또는 로컬 감사 파일에 출력한다.

### 6.2 장면과 캡처 대상

사용자는 `AI Capture` 전용 프로필·장면 컬렉션을 만들고 허용 장면에 창 캡처 또는 특정 창 모드의 게임 캡처 한 개를 등록한다. 승인 정책은 OBS 장면·소스 식별자(UUID 지원 시 우선), 입력 종류, 창 매칭 설정을 고정한다. OBS 장면은 승인된 소스 하나가 켜져 있어야 한다. 중첩 장면, 그룹, 미검증 필터와 추가 입력은 거부한다.

OBS 설정 검증과 실제 Windows 창 확인을 각각 수행한다. OBS의 제목 일치 우선순위를 고정하고, 등록할 때 확인한 정확한 제목·클래스·실행 파일 절대 경로를 Windows에서 조회한다. OBS가 선택할 수 있는 같은 제목의 창이 복수이거나 창이 최소화·종료·변경되어 식별을 확정할 수 없으면 거부한다. 승인 화면에는 사용자가 OBS의 실제 화면을 로컬에서 확인하는 단계가 있다. 승인 직전과 직후, PNG 결과 수신 후 저장 직전, 녹화 감시 주기에 창 핸들·프로세스 식별값과 설정을 대조한다. 설정값과 Windows 창 조회만으로 OBS가 실제 사용 중인 창을 완전히 증명하기 어려우므로, 실기에서 대상과 미리보기를 확인하고 확정할 수 없는 캡처 모드는 사용 범위에서 제외한다.

장면 전환은 `obs_select_target`으로 승인받아 수행한다. 전용 컬렉션에서 유효 전환은 Cut으로 고정하고, 장면별 전환 재정의가 없는지 확인한다. `SetCurrentProgramScene` 후 3초 안에 `GetCurrentProgramScene`의 실제 ID와 `GetCurrentSceneTransitionCursor`의 비활성 상태를 확인한다. 상태가 어긋나거나 제한 시간이 지나면 `TARGET_CHANGED`를 반환한다. 캡처나 녹화 직전에도 최종 프로그램 장면·소스·창·방송·가상 카메라를 다시 확인한다. 이미 활성인 녹화 중 PNG를 허용하는 경우, 확인된 MCP 소유 세션의 동일 대상에만 새 승인을 받아 실행한다.

오디오는 기본 무음이다. 전용 프로필의 Desktop Audio·Mic/Aux·별도 오디오 입력을 비활성화하고, 창 캡처 오디오 옵션과 트랙 설정을 점검한다. 오디오 안전 상태를 확정할 수 없으면 시작을 거부한다. 예상과 다른 창이 검출돼도 전체 화면이나 다른 창으로 전환하지 않는다.

### 6.3 스크린샷

1. 허용 대상과 프로필·장면을 재검증하고 로컬 사용자 승인 후 다시 상태를 확인한다.
2. 같은 루프백의 PNG 전용 연결에서 `GetSourceScreenshot`에 승인된 sourceName/UUID, `imageFormat=png`, 제한된 크기만 전달한다. 1회에 캡처 하나만 처리한다. 제어 연결과 녹화 감시의 수신·디코딩·저장 시간을 분리한다.
3. 44 MiB WebSocket 메시지 한도를 적용한다. 32 MiB PNG의 Base64 길이는 약 42.7 MiB이므로 JSON 오버헤드를 수용한다. 디코딩 전에 Base64 길이가 `4 × ceil(32 MiB / 3)` 이하인지 검사하고, 디코딩 바이트 길이도 제한한다. data URI·MIME·Base64·PNG 서명과 파일 무결성을 확인하고, 가로·세로는 각각 최대 4096 픽셀로 제한한다. 크기 초과나 손상은 저장 없이 거부하고 PNG 연결만 닫는다.
4. 프로그램 장면과 승인 창의 상태를 저장 직전에 다시 확인한다. 서버가 생성한 파일명을 사용해 지정 디렉터리에 배타 저장하고 파일 크기·유효성을 확인한다. `SaveSourceScreenshot`을 사용해 OBS에 임의 경로를 직접 전달하지 않는다.
5. MCP 응답에는 메타데이터만 포함한다. 이미지 자체를 AI에 반환하거나 업로드하는 기능은 기본 제외한다. 사용자가 별도로 파일을 열거나 에이전트에 제공하면 해당 AI 서비스로 콘텐츠가 전달될 수 있다.

### 6.4 녹화 상태 머신

```text
IDLE → APPROVAL → STARTING → RECORDING ↔ PAUSED
                                  │          │
                                  └──→ STOPPING → FINALIZING → FINISHED
제어 연결 손실 / 이벤트 유실 / 상태 불일치 → UNKNOWN → 상태 조회 / 수동 확인
```

- **소유권 부여.** 시작 직전 연결과 `GetRecordStatus`의 비활성 상태를 확인하고, 승인된 요청을 한 번 송신한다. 같은 제어 연결에서 해당 `StartRecord`의 성공 응답, 이후의 `RecordStateChanged` 시작 상태, 활성 상태 조회가 모순 없이 이어질 때만 소유 세션으로 확정한다. 응답과 이벤트는 도착 순서가 바뀔 수 있으므로 송신 시점부터 모두 관찰한다. OBS 이벤트에 MCP 세션 ID가 없으므로 관찰이 이어지는 동안만 소유권을 인정한다. 전용 프로필을 사용하는 동안 수동 또는 다른 도구의 녹화 시작을 금지하며, 애매한 이벤트는 소유로 간주하지 않는다.
- **일시정지와 감시.** 소유권이 확인된 세션에만 `PauseRecord`와 `ResumeRecord`를 사용하며 출력 형식이 이를 지원하지 않으면 명시적으로 오류를 반환한다. 시작 요청 송신부터 단조 시계로 흐른 시간을 계산한다. 일시정지 시간도 포함하고 재개 시 마감은 그대로 유지한다. 1초마다 `GetRecordStatus.outputBytes`, 녹화 볼륨 여유 공간, 장면·창·출력 프로필과 안전 상태를 확인한다. 시간 도달, 출력 2 GiB 이상 또는 여유 공간 1 GiB 이하에서 소유 녹화만 중지한다. `outputBytes`는 출력량이므로 실제 MKV 크기는 종료 후 확인한다. OBS 응답·인코더 버퍼·감시 간격으로 생긴 초과는 기록한다.
- **종료와 파일 확인.** 사용자 요청, 자동 중지, 정상 서버 종료는 같은 중지 절차를 사용한다. 같은 세션을 연속 관찰한 `STOPPED` 이벤트 또는 현재 중지 요청의 응답에서 `outputPath`를 얻는다. 둘 다 수신하고 서로 다르면 결과를 확정하지 않는다. 비활성 상태를 확인하고 §4.3의 새 MKV 검증을 수행한다. 수동 OBS 종료도 동일 세션의 종료가 연속 관찰되면 `OBS_STOPPED`로 기록한다. 파일 검증은 최대 5초 동안 수행하고 크기 안정화·읽기 가능 여부를 확인한다. 재생 검사를 수행하지 않았다면 `playback_verified=false`로 반환한다.
- **결과 재조회.** 완료 결과와 파일 검증 실패를 세션 ID로 키를 지정해 전용 로컬 디렉터리에 원자적으로 기록한다. 24시간 동안 최대 100건을 유지하고 가장 오래된 항목부터 만료한다. 절대 경로나 OBS 원본 응답은 기록하지 않는다. 종료 뒤 `obs_record_status(session_id)`와 같은 ID의 `obs_record_stop`은 보관된 결과를 반환한다. 중지 진행 중 중복 호출은 진행 상태를 반환하며 두 번째 중지 RPC를 발행하지 않는다. 재실행 시 완료 결과만 불러오고 활성 녹화의 소유권은 복원하지 않는다.
- **불확실한 상태.** 연결 단절·이벤트 유실·응답 타임아웃·모순을 감지하면 `STATE_UNKNOWN`으로 전환한다. 상태 조회만 허용하고 시작·일시정지·재개·자동 중지 RPC는 보류한다. 예상치 못한 종료 또는 새 시작이 관찰되면 이전 세션의 제어권을 폐기한다. 재연결 후 활성 녹화의 소유권을 자동 복구하지 않고 OBS에서 수동 확인·종료하도록 안내한다. 녹화가 비활성이고 정책 재검증이 끝나면 새 사용자 승인을 받아 새 세션을 시작할 수 있다. `StopRecord` 응답이 유실됐더라도 단절 없이 해당 녹화의 종료 이벤트가 확인되면 그 경로로 파일을 검증할 수 있다. 상태 변경 RPC를 재송신하지 않는다.
- **프로세스 종료.** 정상 종료 시 소유가 확인된 녹화만 정지한다. 강제 종료·PC 장애·연결 손실 중에는 녹화가 지속될 수 있어 OBS의 수동 종료 버튼을 안내한다. 프로세스 종료 뒤에도 자동 정지가 필수라면 OBS 출력의 동일성을 독립적으로 확인하는 신뢰된 별도 감시 프로세스를 차기 버전에서 설계하고 실기 검증한다.

### 6.5 동시성

Codex와 Claude Code에 동일 MCP를 등록할 수 있지만, v1은 한 번에 하나의 활성 MCP 서버가 OBS를 제어한다. Windows 사용자/OBS 인스턴스별 named mutex 등 검토된 OS 동기화 수단으로 서버 수명 전체에 걸친 단일 제어권을 보장한다. 두 번째 서버는 명확한 `BUSY` 또는 초기화 오류를 반환한다. 한 프로세스 안의 상태 변경과 송신은 짧은 임계 구역에서 직렬화한다. 사용자 승인 대기, 전환 완료 대기, PNG 송수신·검증, 파일 안정화 중에는 녹화 감시가 진행되도록 한다. 동시 클라이언트 지원은 공유 로컬 브로커 설계 및 별도 보안 검토 후 확장한다.

## 7. 설정 및 설치 절차

### 7.1 사용자 전용 설정 예시 (실제 비밀번호 미포함)

아래는 구현해야 할 설정 스키마의 예시이며 현재 작동하는 프로그램 설정 파일이 아니다. 경로·입력 종류·창 식별자는 실제 환경에서 사용자가 확인 후 등록한다.

```toml
[storage]
root = 'D:\OBS-Captures'
min_free_bytes = 1073741824
max_record_bytes = 2147483648

[policy]
profile = 'AI Capture'
scene_collection = 'AI Capture'
max_record_seconds = 120
require_local_approval = true
allow_audio = false

[[targets]]
id = 'unity_game'
scene = 'Unity Game'
source = 'Unity Window'
input_kind = 'window_capture'
# 실제 OBS 버전에서 읽은 창 매칭 설정은 별도 등록/검증한다.
```

설정은 에이전트가 자동 생성·변경하지 않고 사용자가 별도 설정 절차를 통해 승인한다. 필수 설정이 누락되거나 정책이 변조되면 기본 거부 상태로 시작한다. 실제 설정에 `allow_audio=true`, `require_local_approval=false` 등을 넣어도 v1 안전 정책을 우회할 수 없도록 한다.

### 7.2 OBS 설정 (사용자 수행)

1. OBS Studio 실행 → 도구 → WebSocket 서버 설정 → 서버 활성화, 포트 4455, 인증 활성화 및 강한 전용 비밀번호 지정.
2. LAN·인터넷에서 해당 포트로 접근할 수 없도록 Windows 방화벽 및 라우터 설정을 확인한다. 루프백 연결이 작동하는지 검증한다. MCP는 방화벽을 자동 수정하지 않는다.
3. `AI Capture` 전용 프로필과 장면 컬렉션을 생성하고 별도 녹화 폴더, 고급 출력의 표준 MKV, 고유 파일명 규칙, 덮어쓰기·자동 분할·자동 리먹스·오디오 비활성화를 설정한다. Cut을 선택하고 장면별 전환 재정의를 확인한다. 기존 일반 OBS 환경은 보존한다.
4. 허용 대상 창을 등록하고 OBS 미리보기로 실제 창과 캡처 내용이 일치하는지 확인한다.
5. MCP의 로컬 설정 도구로 대상·경로·비밀번호를 등록한다. 사용자 비밀번호 입력은 에이전트 대화창이 아닌 로컬 자격증명 등록 UI에서 직접 수행한다.

### 7.3 빌드와 MCP 등록 (구현 완료 후)

설치 예시는 구현자가 제공할 패키지 구조와 로컬 경로를 전제로 한다. 아래 `C:\Tools\secure-obs-mcp`는 예시다. 실제 배포 명령은 잠금 파일 및 테스트 결과와 함께 제공한다.

- 프로젝트를 Unity 저장소와 별개로 배치한다. `.venv` 생성 후 검토된 잠금 파일로 해시 검증 설치한다. 코드 및 테스트가 통과하기 전 MCP를 등록하지 않는다.
- 실행 진입점은 전용 가상환경 Python의 절대 경로와 `-I -m secure_obs_mcp`로 통일한다. `--self-check` 같은 관리 모드는 별도 진입점에서 실행하고 MCP로 노출하지 않는다.
- Codex 설정 예시 (`~/.codex/config.toml`):

```toml
[mcp_servers.secure_obs]
command = 'C:\Tools\secure-obs-mcp\.venv\Scripts\python.exe'
args = ['-I', '-m', 'secure_obs_mcp']
tool_timeout_sec = 60
cwd = 'C:\Tools\secure-obs-mcp'
```

- Claude Code PowerShell 등록 예시 (로컬 프로젝트 범위):

```powershell
claude mcp add --transport stdio --scope local secure-obs -- 'C:\Tools\secure-obs-mcp\.venv\Scripts\python.exe' -I -m secure_obs_mcp
```

검증된 빌드를 전용 가상환경에 설치한다. 동명 모듈을 작업 폴더와 `PYTHONPATH`에 둔 시험에서 설치된 모듈만 불러오는지 확인한다. 두 클라이언트의 설치 버전에서 등록 옵션을 확인하고 기존 설정을 덮어쓰지 않는다. 환경변수 대체 인증을 선택했다면 클라이언트별 안전한 환경변수 전달 설정을 검증하되 실제 비밀번호는 설정 파일에 넣지 않는다. 로컬 MCP 도구 목록과 `obs_status` 결과로 연결을 확인한다. 기존 승인 정책은 유지하며 무조건 허용 모드는 설정하지 않는다. 원격/클라우드 에이전트에서 사용자의 로컬 OBS에 직접 연결되는 것으로 가정하지 않는다.

## 9. 선택 확장 (v1 합격 후에만)

AI가 직접 특정 창으로 캡처 대상을 바꾸는 기능은 편리하지만, 창 목록 자체가 개인 정보를 포함할 수 있고 OBS의 소스 설정이 다른 창으로 연결될 수 있다. v1에서 사전 등록 장면 전환만 지원하는 이유다.

확장 시 `GetInputPropertiesListPropertyItems`로 승인된 창 캡처 소스의 `window` 속성 후보를 얻고, 실제 Windows OBS에서 속성명과 값 형식을 확인한다. 사용자 허용 실행 파일/창에 해당하는 후보만 노출하며 임의 창 목록 전체를 반환하지 않는다. 사용자가 고른 값으로 `SetInputSettings`의 허용된 단일 속성만 변경하고, 다른 필드는 거부한다. 생성·삭제·URL·임의 입력 설정은 여전히 금지한다. 창 재검증 및 승인, 녹화 중 변경 금지, 변경 전후 상태 검사와 롤백 테스트를 통과해야 한다. 자동 녹화 시나리오·영상 미리보기·멀티 클라이언트 브로커도 별도 확장으로 취급한다.

## 10. 검증 및 인수 테스트

실제 OBS를 건드리지 않는 자동 단위/통합 테스트를 먼저 실행한다. 거부 시험에서 위험 RPC가 가짜 OBS 서버에 한 건도 도달하지 않아야 한다. 실제 OBS 시험은 사용자 승인 후 전용 테스트 프로필과 민감정보 없는 테스트 창으로만 수행한다. 방송 차단 시험은 모의 상태로 검증하며 실제 방송을 시작하지 않는다.

| ID | 시험 | 합격 기준 |
|---|---|---|
| T01 | 정상 연결 및 상태 | MCP 도구 목록 확인, 정확한 OBS 버전/상태 출력 |
| T02 | OBS 미실행/틀린 암호/인증 꺼짐 | 명확한 오류, 무한 재시도 없음, 비밀번호 노출 없음 |
| T03 | 외부 URL, IPv6 우회, 프록시 환경변수, 리다이렉트 | 루프백 외 연결 시도 0건, 요청 차단 |
| T04 | 금지 RPC·원시 요청·추가 인자 | 모든 요청 차단, OBS까지 전송되지 않음 |
| T05 | 승인 취소·타임아웃·가짜 confirmed 인자 | 캡처/녹화 시작 요청 0건 |
| T06 | 허용되지 않은 장면·창, 다른 프로필, 예상 외 소스/필터/오디오 | 거부, 자동 전체 화면 대체 없음 |
| T07 | PNG 정상 캡처 | 지정 루트에 새 PNG 생성, 실제 화면·크기 확인, 모델에 이미지 바이트 미반환 |
| T08 | 잘못된 base64/과대 이미지/손상 PNG | 저장 거부 또는 해당 호출의 불완전 파일만 정리 |
| T09 | 경로 탈출·UNC·ADS·예약명·junction·symlink·기존 파일 | 루트 밖 파일 생성 및 덮어쓰기 0건 |
| T10 | 실제 녹화 시작→상태→종료 | OBS REC 표시, 결과 파일 루트 내 저장, 재생 가능 확인 |
| T11 | 일시정지·재개·중복 시작·잘못된 세션 | 올바른 상태 전이, 지원하지 않으면 명시 오류, 기존 수동 녹화 보존 |
| T12 | 방송/가상 카메라 활성 모의 상태 | 캡처/변경 요청 거부, 방송 제어 요청 0건 |
| T13 | 제한 시간·용량·디스크 부족 | 자신이 시작한 녹화 안전 정지 또는 명확한 실패 경고 |
| T14 | OBS 연결 끊김·MCP 정상/강제 종료 | 성공 가장 없음, 정상 종료 시 정지 시도, 강제 종료 잔여 위험 및 수동 복구 확인 |
| T15 | 두 MCP 동시 실행 | 하나만 제어권 획득, 다른 서버는 BUSY 또는 명시 오류 |
| T16 | 비밀·캡처 데이터 로그 검사 | 실제 비밀번호, 인증 응답, 원시 이미지, 개인 창 제목 및 불필요한 절대 경로 미포함 |
| T17 | 런타임 네트워크 검사 | MCP 프로세스에서 예상된 루프백 통신 외 외부 연결 없음 (OBS 자체 통신과 구분) |
| T18 | Codex / Claude Code 실제 연결 | 각 클라이언트에서 상태→스크린샷→녹화→종료 성공, 순차 검증 |
| T19 | 창 최소화/종료/제목 변경/장면 전환 | 타 창으로 무단 전환하지 않음, 불확실하면 실패/정지/경고 |
| T20 | 실제 녹화 무음 검증 | 오디오 입력이 포함되지 않는 설정 확인, 결과 음성/오디오 트랙 검사 |

실기 검증 시 사용할 사용자 요청 예시:

> OBS MCP로 승인된 Unity Game 장면의 상태를 확인해. 내 로컬 승인 후 PNG 스크린샷을 한 장 저장하고, 승인된 같은 창을 10초간 무음 녹화한 뒤 종료해. 저장된 파일의 상대 경로와 실제 녹화 상태를 알려줘. 외부 전송이나 OBS 일반 프로필 변경은 하지 마.

10초 녹화는 MCP 감시자가 종료한다. 호스트는 저장된 세션 ID로 결과를 조회한다. 사용자 로컬 환경에서 실제 영상 재생, 타깃 일치, 무음 확인까지 완료해야 최종 합격이다.

### 10.1 우선 인수 시험과 성능 측정

| ID | 시험 | 합격 기준 |
|---|---|---|
| T21 | 10초 자동 종료 후 조회 및 재중지 | `TIME_LIMIT`, 동일한 검증된 상대 경로와 바이트 수 반환, 중지 RPC는 최초 1건. 재실행 후 보관 기간 내 결과 조회 가능. Codex와 Claude Code에서 각각 재생·무음 확인 |
| T22 | 연결 단절 중 수동 녹화로 교체 | 재연결 뒤 이전 ID에 `STATE_UNKNOWN`. 활성 수동 녹화 중지·일시정지·재개 RPC 0건 |
| T23 | 승인 창이 열린 중 녹화 한도 도달 | 다음 1초 감시 주기에 소유 녹화 중지 시작. 만료 이후 클릭에서 캡처 송신 0건 |
| T24 | 중복 창·전환 지연 | 설정과 실창이 불일치하거나 전환이 완료되기 전 StartRecord·PNG 요청 0건 |
| T25 | PNG 전송 상한 | 1 MiB를 넘는 정상 메시지는 저장. 44 MiB 전송·32 MiB PNG·4096 픽셀 상한을 각각 초과하면 저장 0건, 제어 연결 유지 |
| T26 | 출력 모드·검증 실패 | 필수 프로필 키가 검증되지 않으면 StartRecord 0건. 종료 경로가 범위를 벗어나거나 기존 파일이면 결과 경로 미반환 |
| T27 | Python 실행 격리 | 작업 폴더와 `PYTHONPATH`에 동명 모듈이 있어도 전용 가상환경의 설치본만 실행 |

성능 시험은 같은 Unity 장면·동작을 무녹화, 1080p 하드웨어 인코딩 녹화, 같은 녹화의 중간에 PNG 1회 캡처하는 조건에서 각각 60초간 실행한다. OBS 통계에서 렌더링 지연과 인코딩 지연 프레임 수의 구간별 증분을 기록한다. Unity 프레임 시간 p95와 PNG 처리 구간의 최대 프레임 시간, 실제 해상도·FPS·인코더를 함께 기록한다. 하드웨어 인코딩을 쓸 수 없는 환경은 해당 조건을 미측정으로 표시한다.

## 11. 구현 단계 및 최종 제출물

1. 공식 사양·SDK 버전 및 의존성 검토, 위협 모델 정리, 설계 확정.
2. 로컬 정책·RPC 제한·인증·경로·승인 UI·동시성 통제 구현.
3. 상태 확인·장면 선택·PNG 저장 구현 및 단위 테스트.
4. 녹화 상태 머신·감시·오류 복구 구현 및 모의 통합 테스트.
5. 공급망 검사, 정적 보안 검토, 비밀 검색, 네트워크/파일 경계 시험.
6. 사용자 승인 후 전용 OBS 프로필에서 실제 테스트 및 클라이언트 순차 연결 검증.
7. 검증 결과를 제출하고 사용자가 승인한 뒤 설치/등록 확정.

최종 제출물: 전체 소스, 잠금 파일, 설치·제거·비밀번호 등록·긴급 정지 가이드, 도구 목록 및 RPC 허용 목록, 테스트 코드와 결과(통과/실패/미실행 구분), 사용 의존성 및 라이선스, 보안 검토 결과 및 잔여 위험, 실제 OBS 시험 버전·클라이언트 버전·결과물 경로. 사용자가 직접 요청하지 않았다면 GitHub 공개, 커밋·푸시, 기존 Unity 프로젝트 수정, 전역 설정 변경은 하지 않는다.

**완료 조건:** 필수 기능 구현과 자동 테스트 통과만으로 실제 OBS 연결 성공을 주장하지 않는다. 실제 Windows OBS와 Codex 및 Claude Code에서 T07/T10/T18/T20/T21을 검증하고 모의 회귀 시험 T22–T27의 결과를 확인한 후에만 운영 가능으로 보고한다. 미실행·실패 시험, 접근 제한, 미검증 의존성은 그대로 표시한다. 확인하지 않은 사항에 대해 '완전히 안전하다'는 표현을 사용하지 않는다.

## 12. 코딩 에이전트에게 전달할 최종 작업 지시

> 이 문서를 구현 계약으로 사용하여 독립적인 Windows 로컬 OBS MCP 서버를 개발해라. 먼저 공식 OBS WebSocket 5.x 및 MCP SDK 사양과 설치 환경을 확인하고 구현 계획·예상 의존성·위협 모델을 제시해라. 보안 정책과 RPC 허용 목록을 구현한 뒤 스크린샷/녹화 기능을 구현하고 자동 테스트를 실행해라. 기능을 위해 보안 제한을 완화하지 말고, 공식 API에서 확인되지 않은 기능은 실제 지원 여부를 확인하거나 미지원으로 처리해라. 실제 비밀번호를 요구하거나 읽어서 보여주지 말고, 사용자가 로컬에서 직접 등록하도록 안내해라. 실제 OBS 설정 변경·실기 녹화·Codex/Claude 설정 등록·전역 설치·커밋/푸시는 사용자 승인 이후에만 진행해라. 테스트 결과와 잔여 위험, 수동 긴급 정지 및 제거 방법까지 제출해라. 네트워크 제한 등으로 검증하지 못한 내용은 성공으로 표시하지 마라.
