# 교훈 관리 및 재발 방지 정책 (Lesson Policy)

## 1. 목적

개발 과정에서 발생한 실수, 설계 오류, 보안 문제 및 검증 실패의 원인을 기록하고 이후 작업에서 동일한 문제가 반복되지 않도록 한다. 교훈은 모든 개발 에이전트가 공유하는 지식으로 관리한다.

## 2. 작업 시작 전

- `AGENTS.md`, 현재 작업 명세 및 본 정책을 확인한다.
- `init/rules/lessons/`에서 현재 작업과 관련된 교훈을 검색하고 읽는다.
- 관련 교훈의 재발 방지 규칙을 구현 및 테스트 계획에 반영한다.
- 기존 교훈이 현재 코드 및 명세에도 유효한지 확인한다.

## 3. 교훈 기록 대상

다음과 같은 상황에서 재발 방지 가치가 있는 교훈을 기록한다.

- 잘못된 구현 및 설계 판단
- 사용자 피드백에 따른 오류 수정
- 공식 API 및 라이브러리 사용 오류
- 보안 정책 위반 또는 취약점 발견
- 테스트 실패 및 잘못된 검증 결과
- 운영체제 및 버전 호환성 문제
- Git 브랜치 및 PR 관리 실수
- 반복적으로 발생하는 성능 및 안정성 문제
- 기존 작업 결과의 손상 또는 의도하지 않은 변경

단순한 작업 진행 내역이나 일시적인 오류는 기록하지 않는다.

## 4. 파일 관리 규칙

- 저장 위치: `init/rules/lessons/`
- 파일명: `YYYY-MM-DD-issue번호-주제.md`
- 관련 이슈가 없다면 이슈 번호는 생략한다.
- 교훈 하나당 하나의 독립된 Markdown 파일을 생성한다.
- 파일당 200줄 이내를 원칙으로 한다.
- 공용 교훈 목록에 내용을 누적하지 않는다.
- 기존 교훈과 중복되는 기록을 생성하지 않는다.
- 기존 교훈을 수정할 때는 변경 근거를 명시한다.
- 관련 이슈 및 검증 근거를 연결한다.

## 5. 교훈 작성 양식

### 제목

- 발생 날짜:
- 관련 이슈 및 PR:
- 관련 모듈:
- 분류 및 검색 태그:
- 발생한 문제:
- 근본 원인:
- 해결 방법:
- 재발 방지 규칙:
- 검증 방법 및 결과:
- 적용 범위 및 한계:

확인되지 않은 원인은 추측으로 구분하고, 수행하지 않은 검증을 성공으로 기록하지 않는다.

## 6. 보안 관련 기록 제한

- 비밀번호, 인증 정보, API 키 및 개인 데이터를 기록하지 않는다.
- 실제 스크린샷, 녹화 영상, 민감한 로그 및 개인 파일 경로를 포함하지 않는다.
- 미해결 취약점의 상세 내용과 악용 가능한 재현 절차를 공개 저장소에 기록하지 않는다.
- 민감한 보안 발견 사항은 `SECURITY.md`의 비공개 제보 정책에 따라 관리한다.
- 교훈을 근거로 기존 보안 정책을 임의로 완화하거나 우회하지 않는다.

## 7. 재발 방지 검증

- 교훈을 작성하는 것만으로 문제가 해결되었다고 판단하지 않는다.
- 코드 수정이 필요한 문제는 가능한 경우 회귀 테스트를 추가한다.
- 반복 발생하는 문제는 공통 검증 절차 또는 자동화 테스트로 관리한다.
- 검증에 실패한 항목은 명시하고 성공으로 보고하지 않는다.
- 근본 원인과 수정 결과가 확인되었는지 구분한다.

## 8. 작업 종료 전

- 현재 작업에서 기록할 가치가 있는 교훈이 발생했는지 확인한다.
- 관련 교훈의 재발 방지 규칙을 준수했는지 확인한다.
- 필요한 경우 새로운 교훈 파일을 생성한다.
- 작업 결과 보고에 추가된 교훈 파일과 검증 결과를 명시한다.
- 교훈이 발생하지 않았다면 형식적인 기록을 생성하지 않는다.

## 9. 정책 우선순위

교훈은 기존 개발 명세 및 보안 요구사항을 보완하는 자료이며 이를 대체하지 않는다. 기존 교훈과 최신 명세가 충돌하는 경우 임의로 판단하여 보안 정책을 변경하지 말고 충돌 내용을 보고한다.

새로운 교훈이 공통 개발 규칙의 변경을 요구하는 경우 별도 검토 및 관리자 승인을 거쳐 반영한다.
